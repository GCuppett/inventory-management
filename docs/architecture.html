Architecture Overview

Factory Inventory Management System

A full-stack demo app for inventory tracking, order management, demand forecasting, and spending analytics across factory warehouses. No database — all data is loaded from JSON files into memory at server startup.

01 Tech Stack

Client

Vue 3 + Vite

localhost:3002
  • Composition API throughout
  • vue-router (client-side SPA routing)
  • axios for HTTP calls
  • Custom SVG charts, no chart library
  • Lightweight i18n (en / ja)
Server

Python FastAPI

localhost:8001
  • Pydantic models for validation
  • Plain function-based route handlers
  • CORS wide open (allow_origins=["*"])
  • Auto-generated docs at /docs
  • Filtering done in-process, no query engine
Data

In-memory JSON

server/data/*.json
  • Loaded once at process startup
  • 7 JSON files: inventory, orders, demand, backlog, spending, transactions, purchase orders
  • No persistence — edits are lost on restart
  • No auth, no rate limiting (demo only)

03 Frontend Structure

Views — one per nav tab

  • Dashboard.vue — summary + key metrics
  • Inventory.vue — stock across warehouses
  • Orders.vue — order status tracking
  • Demand.vue — forecast trends
  • Spending.vue — cost analytics
  • Reports.vue — quarterly / monthly rollups
  • Backlog.vue — delayed items + purchase orders

Shared modules

  • api.js — single axios client, all HTTP calls
  • useFilters.js — warehouse / category / status / month state
  • useAuth.js — mock signed-in user, no real auth
  • useI18n.js + locales/en.js, ja.js
  • components/ — FilterBar, modals, ProfileMenu

05 Known Gap

Frontend/backend mismatch: client/src/api.js defines getTasks(), createTask(), deleteTask(), toggleTask(), createPurchaseOrder(), and getPurchaseOrderByBacklogItem() — calling /api/tasks and /api/purchase-orders. Neither route exists in server/main.py. Tasks in the UI are currently backed entirely by mock data in useAuth.js; any call that reaches the real API for tasks or purchase orders will 404. This is a genuine gap in the current backend, not just a doc discrepancy — the code you'd copy from this repo's api.js won't work until those routes are added.
